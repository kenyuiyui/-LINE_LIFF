這裡是真的：點擊上方按鈕會跳出瀏覽器的麥克風權限請求，同意後即為真實的 Web Speech API 語音辨識，請對著裝置說話測試。若卡在「無法開始錄音」，畫面會顯示實際錯誤原因（權限被拒 / 網路問題 / 瀏覽器不支援），不是我用文字猜的。

這次修正：引擎每講一兩句就自動重啟是系統本身的行為，改不了；但現在重啟不會再打斷你正在講的長句——內容會持續累積，直到真的停頓夠久（約 2.5 秒）或講出標點符號才切成卡片。新增：會議中畫面現在會即時顯示「剛新增的那張卡片內容」，不用切到編輯頁才看得到。

連續修了三次的 bug（老實記錄，方便你判斷這輪穩不穩）：第一版疊加 bug 導致同一句話重複六遍；第二版修疊加時改用長度比對，結果把「引擎修正字詞但長度不變」的情況整段漏掉，導致長句消失；第三版改用共同前綴比對，又在「句子中間單字被修正」時產生混亂拼接。第四版改回 Chrome 官方示範的標準寫法：session 內用 resultIndex 累加（不用自己比對差異），只在 session 真正結束（onend）時才把內容搬進跨 session 緩衝區，並補上「使用者中途按停止、最後一段話不會消失」的處理。

第五版新修：真機測試發現唸連續數字（1、2、3…10）時，引擎會把每次逐步累加的中間判斷都當成正式 final 結果送出，導致卡片內容變成「111 21 21 2 31 2 31 2 3…」這種混亂疊加。已加防禦，若新收到的內容整段包含上一段內容當開頭，就用新的取代舊的而非相加。

第六版新修（依你提供的三組真機重複資料）：發現一般對話（非數字）也會出現整段句子重複兩三次的情況，且重複的內容常帶有引擎自行修正的一兩個字差異（例如「最弄的」被修正成「最後的」），不是逐字複製。這次不再猜測特定重複形狀，改成在最終文字裡直接找「有沒有一段內容跟後面高度相似（容許少量字差）」，找到就去掉重複的前段。用你提供的三組真實資料測試：一組完全符合預期，兩組大幅改善但仍殘留兩三個字的誤差（三層以上疊加又夾雜修正時，切割點不一定完全精準）。這是目前用簡單方法能做到的程度，如果測試發現誤差比例仍偏高，代表需要更複雜的比對演算法，屆時再往下調整。
